# 玩家连接审计

中心接收 `realmmesh.audit.v1.AuditService/ReportPlayerConnectionEvent`，在普通服务启动迁移时创建 `player_connection_events` 表。只有带有效游戏服凭据的请求可以写入，服务器 ID 来自认证结果，请求正文不能指定。

游戏服每次进服生成新的 UUID，同次离服使用相同 ID。进服记录不代表账户登录成功：未注册和未登录玩家同样可以产生记录。中心不因此创建账户，也不维护在线会话。

| 数据 | 含义 |
| --- | --- |
| `id` | 中心雪花 ID |
| `server_id` | 已认证的游戏服身份 |
| `connection_id` | 一次游戏连接的 UUID，用于关联进服和离服 |
| `player_name` | 游戏服取得的真实玩家名字，保留大小写 |
| `event_type` | 1 表示进服，2 表示离服 |
| `occurred_at` | 游戏服观察到事件的时间 |
| `received_at` | 中心处理请求时记录的时间 |

表另保留项目通用的创建、更新时间和软删除字段。本接口只追加记录，不修改历史记录。索引覆盖“服务器 + 连接 ID”和“大小写归一玩家名字 + 接收时间”。没有账户或服务器外键级联，不因账户删除而丢失审计事实。

单条插入不额外开启事务。写入成功才返回空响应；非法参数返回 `InvalidArgument`，无效凭据返回 `Unauthenticated`，写入失败返回固定 `Internal`，取消和截止期限保留对应状态。

Mod 异步上报并复用现有 RPC 超时，不自动重试、排队补报或等待审计完成。审计不可用不影响认证与门禁自身的规则。停服时通道可能已关闭，崩溃也可能没有离服记录；不保证完整、有序或恰好一次投递。超时后记录是否写入不确定，连接 ID 不是幂等键。

不采集密码、服务器密钥、JWT、完整命令、IP、坐标或任意附加正文。首期没有审计查询 HTTP API，也没有自动保留期或清理任务；表容量随事件数量增长，应由部署方按实际规模安排归档。注册、登录和其他中心业务的审计属于后续步骤。
